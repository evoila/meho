## Note
An approval in the web console asks for the same sign-in level as one on the command line. The console has a second Keycloak client, `meho-web-approve` (backplane setting `UI_KEYCLOAK_APPROVE_CLIENT_ID`), with the secret of `meho-web`, bound to the login flow `meho approval sign-in level`. It is used only for the new sign-in before an approve; the normal console login does not change. `APPROVAL_SIGN_IN_LEVEL` counts for the console too: under `required` (and under `auto` when this client's binding is right) the Approve button needs this sign-in with the level `meho-approve`, and a normal console session gets a **Sign in to approve** link instead. Under `observe` the console approves as before and records the level it saw. `/api/v1/health` shows the console's client in `approvals.web_sign_in` and `approvals.web_sign_in_level_in_force`, and `approvals.sign_in_level_warning` also warns when the console does not require the level. Migration `0173` adds the column `web_session.approval_token` that may be empty; no existing row changes.

## Action
**Action needed when people sign in only through a company login:** on built-in Keycloak with the default `auto`, the upgrade adds the client `meho-web-approve` and binds it, and from then on the console needs the approval sign-in level. A person who signs in only through a company login then cannot approve in the console and not on the command line, until they have a MEHO password and a one-time code. Give these approvers a MEHO password and a one-time code, or set `APPROVAL_SIGN_IN_LEVEL=observe` for now. **Built-in Keycloak:** nothing else to do. **Your own Keycloak:** create `meho-web-approve` with the secret of `meho-web` and the redirect URI `https://<host>/ui/auth/approval-callback`, then run `meho admin keycloak bootstrap-clients` or bind it to the flow by hand ([The console approval client](https://evoila.github.io/meho/latest/install/keycloak-realm/#the-console-approval-client-meho-web-approve)). Until it exists, `auto` keeps the console as before. Check that `approvals.web_sign_in.state` in `/api/v1/health` is `ok`.
