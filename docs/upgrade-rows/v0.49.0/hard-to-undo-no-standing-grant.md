## Note
With the switch `CUSTOM_POLICY` on, an operation whose own definition says a call is hard to undo (`hard_to_undo`: it deletes, stops or overwrites something for good) counts as a delete. A standing grant of a service login and a run approval do not cover a direct call of it: the call waits for a person. In sandbox mode a delete grant covers it, as for an operation with another delete sign, except for an operation that waits on every call because it can read, write or make a credential. With the switch `CUSTOM_POLICY` on, an automation that calls a hard-to-undo operation alone stops at that call and waits for a person. Where the call has a timer, a person approves inside the timer, or the target puts the old state back. With the switch off, nothing changes. See https://github.com/evoila/meho/blob/main/docs/codebase/policy-classification.md.

## Action
Before you turn `CUSTOM_POLICY` on, list the standing grants this touches with this query on the MEHO database: `SELECT g.tenant_id, g.principal_sub, g.connector_id, g.op_id, d.hard_to_undo FROM service_principal_grant g JOIN endpoint_descriptor d ON d.op_id = g.op_id AND ((d.version = '' AND d.impl_id = '' AND g.connector_id = d.product) OR (d.version <> '' AND g.connector_id = d.impl_id \|\| '-' \|\| d.version AND (d.impl_id = d.product OR d.impl_id LIKE (d.product \|\| '-%')))) AND (d.tenant_id = g.tenant_id OR (d.tenant_id IS NULL AND NOT EXISTS (SELECT 1 FROM endpoint_descriptor o WHERE o.tenant_id = g.tenant_id AND o.product = d.product AND o.version = d.version AND o.impl_id = d.impl_id))) WHERE g.revoked_at IS NULL AND (g.expires_at IS NULL OR g.expires_at > CURRENT_TIMESTAMP) AND d.hard_to_undo IS NOT NULL;` The query reads each grant's operation the way a call of the grant's tenant does: the tenant's own copy of the connector when the tenant has one, else the built-in one. It leaves out revoked and expired grants. Each row is a live grant of an operation that is hard to undo. With the switch on, the grant does not let a direct call of the operation run. Every grant that lets a direct call run with the switch off and not with it on is a row. A row can also be a grant that lets no direct call run with the switch off either, for example of an operation that is turned off for the tenant or that is at risk level `destructive`. Plan for a person to approve those calls. A run approval that lists such an operation stops covering it too; ask a person to approve those calls.
