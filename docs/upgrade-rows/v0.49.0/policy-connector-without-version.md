## Note
With `CUSTOM_POLICY` off (the default), nothing changes: a connector with no version keeps the id it had in the policy (`-`), and every answer is as before. With `CUSTOM_POLICY` on, the policy also names such a connector by its product, the id a call uses (for example `vault`). Each of its operations is then checked twice in each scope, once by the old form `-` and once by the product, and the stricter result counts. So an entry that matches it only by the product can add a wait or raise the risk level. It never takes a wait away, never lowers a level, and never changes the category or the labels: those still come from the old form. With `CUSTOM_POLICY` on, these answers name such a connector by its product: the call check, `meho policy explain`, the bulk edit, the import check, `policy.classify_preview`, the carry-over dry run (one line per product) and the overrides report (`meho connector overrides`). No database migration.

## Action
**Nothing to do** while `CUSTOM_POLICY` is off. Before you turn it on, check the entries whose `connector` pattern matches the product of a connector with no version (for example `vault` or `v*`): they can now make its operations wait or raise their risk level. Run `meho policy carry-over --dry-run` to see which operations each "always wait" entry matches.
