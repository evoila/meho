## Note
In MEHO's own login realm, MEHO now refuses a Keycloak write that can break its own sign-in: `keycloak.client.delete` of a client MEHO signs in with, `keycloak.client.update` of such a client, `keycloak.protocol_mapper.create` on such a client, `keycloak.client_scope.protocol_mapper.update` on a client scope that such a client uses as a default or optional scope, and `keycloak.realm.update` of the login realm. MEHO's own clients are the clients named in `KEYCLOAK_ADMIN_CLIENT_ID`, `CHECK_RUNNER_CLIENT_ID`, `KEYCLOAK_AUDIENCE`, `KEYCLOAK_CLI_CLIENT_ID`, `KEYCLOAK_CLI_APPROVE_CLIENT_ID`, `UI_KEYCLOAK_CLIENT_ID` and `UI_KEYCLOAK_APPROVE_CLIENT_ID`, and `meho-mcp`, `meho-mcp-code` and `meho-mcp-desktop`. On such a client MEHO allows a new name or description, a new redirect address or web origin that keeps the old ones, turning it on, and removing its own login flow. On the approval clients (`KEYCLOAK_CLI_APPROVE_CLIENT_ID` and `UI_KEYCLOAK_APPROVE_CLIENT_ID`) MEHO refuses every change of the login flow, because that flow is the approval sign-in. On the login realm MEHO allows display names, the mail server, the event settings, the languages, turning it on, and setting the browser login flow back to `browser`. MEHO refuses before the request waits for approval and again when it runs, also under a standing grant. The refusal says that a realm administrator makes such a change in the Keycloak admin console. A request that waits for approval from before the upgrade is refused when it runs if it hits one of these cases.

## Action
Make other changes of these clients and of the login realm in the Keycloak admin console. No schema action.
