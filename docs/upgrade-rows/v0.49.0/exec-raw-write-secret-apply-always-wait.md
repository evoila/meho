## Note
Every `k8s.exec` call and every `proxmox.api.write` call waits for a person, and a `k8s.apply` call waits for a person when its manifest holds a `kind: Secret` (in any document or any item of a `List`) or when MEHO cannot read the manifest. No standing grant, no agent grant and no run approval covers these calls, also one made before the upgrade: such a grant stays stored, but each call waits. An override that turns approval off for `k8s.exec` or `proxmox.api.write` leaves it on. Grant create, agent grant create (an exact op id with `auto-execute`) and run approval create refuse `k8s.exec` and `proxmox.api.write`. A `k8s.apply` of other kinds keeps its rules. The approval card says in one line why such a call waits; only a person reads that line. The stored request of a `k8s.apply` of a Secret keeps its manifest only until the run starts or the request ends. Who waits now: a run, or a service login, that used a standing grant, an agent grant or a run approval for one of these three calls now waits for a person at that call. This is also true when the call is one step of a longer run: the run stops at that step until a person approves it.

## Action
Find the grants that name `k8s.exec` or `proxmox.api.write` with `meho service-principals grants list`, `meho agent grant list` and `meho approvals runs list`, and remove them or leave them. For each run or service login that uses one of these calls, or applies a Secret, a person must approve each such call or step in the console or the CLI. Plan for this before you start such a run. No schema action.
