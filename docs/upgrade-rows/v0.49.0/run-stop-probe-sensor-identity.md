## Note
Only the login that started a hosted agent run or a background operation run, or a person with the `tenant_admin` role, or a platform admin, can stop it. Any other caller gets 403 with a text that says who may stop the run, and the run goes on. So an `operator` cannot stop another person's run, and an agent or service login stops only its own runs. For an agent or service login, `POST /api/v1/targets/{name}/probe` checks the same per-target rules as the `targets.probe` operation: a denied login gets 403 and nothing is probed or stored. A sensor edit that changes the connector, operation, params or check of a sensor that runs as another person sets the sensor's `identity_sub` to `__sensor__`; the audit row shows the change. A dashboard file import (`POST /api/v1/checks/dashboard-files/import`, `meho dashboard import`) that changes the connector, operation, target, params or check of such a sensor does the same; the import result and its audit row show the change. No schema migration.

## Action
A script that stops runs with an agent or service login must stop only the runs that login started. A tenant admin or a platform admin stops other runs. A script that probes targets with an agent or service login needs a grant that allows `targets.probe` on each target. A service login also needs a read scope that names the target. An agent whose grant for `targets.probe` needs approval gets 403 from the REST route; it sends the probe as the `targets.probe` operation (`call_operation`), which waits for the approval. A sensor that a dashboard file import changed may now run as `__sensor__`; check the import result when a sensor must keep a person as its identity.
