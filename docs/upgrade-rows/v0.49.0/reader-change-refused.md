## Note
A login with the Reader role that asks for a change gets one plain sentence next to the code `insufficient_role`: "You have the Reader role. A Reader cannot ask for changes, so MEHO did not store or run this call. Ask an admin for a role that may make this change." MEHO stores no approval request and runs nothing. The sentence comes from these places: the policy gate; the REST call route `POST /api/v1/operations/call` and the MCP tool `call_operation`, for an operation that asks for a change; the console call form, for an operation that asks for a change; the REST routes, the console routes and the MCP tools that need the Operator role and do not only read; and the write tools of a hosted agent run. REST and the web console answer `403` with `{"detail": "insufficient_role", "message": "<the sentence>"}`; MCP answers with the error message `insufficient_role: <the sentence>`. A re-run of an approved request by a caller whose role is now Reader is refused the same way. A login with the Reader role changes nothing in the knowledge store, with or without the approver flag. A preview and the pages that only read keep their answer. See https://github.com/evoila/meho/blob/main/docs/codebase/agent-permission-model.md.

## Action
Scripts that check a refused change of a Reader read the code `insufficient_role` (in `detail` on REST and in the console, at the start of the MCP error message). Give a person the role that the change needs: Operator, or Admin for an operation that needs the Admin role. No schema action.
