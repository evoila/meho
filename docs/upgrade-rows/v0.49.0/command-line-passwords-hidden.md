## Note
A password or token on a command line is now hidden. Command lines in operation results, approval cards, traces, broadcast messages and error texts show `[REDACTED:command_line_secret]` in place of the password (for example `mysql -p…`, `sshpass -p …`, `--password …`, `curl -u user:…`, `sqlplus user/…@db` and `Password=…;` in a connection string). The rest of the command line stays readable. Where an answer hid a password whole already, it stays as it was; where it hid only a part of it (for example a quoted password with a space), or did not hide it, the whole password is now hidden. Nothing else changes: every part that was hidden before is still hidden, and every part that was shown before and is not a password is still shown. A value that was hidden already (also an older mark such as `***REDACTED***`, or only `*` characters) stays as it is, and a JSON log line that parsed before, also one inside another JSON document, still parses. A database login is hidden whatever its service name, when a database client such as `sqlplus` or `rman` stands before it. A connection string password without quotes and without a `;` after it is hidden to the end of its line, so a last field with spaces is hidden whole. A quoted password may run over line breaks, but a closing quote more than 64 lines further down does not count, so one quote that is never closed does not hide the log lines after it. A command line with no password is shown as before. The raw copy in an audit row is not changed by this rule.

## Action
None for most operators. A script or a check that reads a password from a command line in a result now gets the hidden mark: read the password from Vault or the target's credentials instead.
