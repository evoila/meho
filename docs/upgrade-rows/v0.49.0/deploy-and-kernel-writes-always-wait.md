## Note
More typed writes wait for a person on every call, and no standing grant, no agent grant and no run approval covers them: every `argocd.app.set`, `argocd.appproject.create` and `argocd.appproject.update`; an `argocd.app.sync` that names a `revision`; and a `linux.sysctl.write` of a key or a value that can make the kernel run a program or write a file. A person's own call of these waits too. The rule: a write that chooses what a system runs later, or who gets rights, waits for a person; a write that only starts what is already defined keeps its rules. So an `argocd.app.sync` without a revision, an `argocd.app.rollback` and a `linux.sysctl.write` of a plain tuning value keep their rules. Grant create, agent grant create and run approval create refuse `argocd.app.set` and the two AppProject writes. A sensor of a call that waits is refused at create and reads `unknown`. Who waits now: a deploy run, a service login, an agent or the automation engine that used a standing grant or a run approval for these calls now waits for a person at each such call.
