## Note
In MEHO's own login realm, in `master` and in the target's admin realm, a platform admin now approves every Keycloak write, and every `secret.move` that reads from or writes to one of these realms. The one exception is a write that sets only keys from a short list that cannot touch sign-in or rights: `displayName` of `keycloak.realm.update`, `name` and `description` of `keycloak.client.update`, and `firstName` and `lastName` of `keycloak.user.update`. When MEHO cannot read which realm a write changes, it counts as the login realm. The approval card says why. Right before an approved write runs, MEHO checks it again. In other realms, the approvers stay the same.

## Action
Many Keycloak approvals in these realms now need a platform admin, where a tenant admin was enough. Make sure a platform admin can approve them. In these realms, no standing grant and no run approval clears a Keycloak write: a call of a service login waits for a person to approve it. A Keycloak write or a `secret.move` with a Keycloak side that was approved before the update and has not run yet is refused when its run starts, in every realm: send it again. No schema action.
