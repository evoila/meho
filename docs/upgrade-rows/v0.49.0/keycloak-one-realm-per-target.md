## Note
A Keycloak target now works on one realm only: the managed realm it names. A call that names another realm is refused before it waits for approval, and nothing is sent to Keycloak. This covers the `realm` value of `keycloak.realm.update`, `keycloak.realm.delete` and `keycloak.user.check_login`, the realm name of `keycloak.realm.create`, and the realm of a `keycloak:` ref in `secret.move` or `secret.handoff.export`. So `keycloak.realm.delete` now deletes only the managed realm of its target; it still never deletes `master`, the target's admin realm or MEHO's own login realm. MEHO now reads the managed realm before every operation, except the one that creates a realm. The MEHO login needs at least one `realm-management` role in that realm (the documented minimum `view-realm`, `view-clients`, `view-users` has it); `keycloak.realm.delete` needs `view-realm` for the realm id. Keycloak must answer with exactly the managed realm, with the same case and accents, else the operation is refused. With the new switch `KEYCLOAK_ANSWER_REALM` on (off by default), every Keycloak answer has a `managed_realm` field that names the realm the call acted on. The approval card of every write shows the realm, and `meho targets describe` shows the admin realm and the managed realm of a Keycloak target together.

## Action
If you made calls that name another realm than the managed realm of the target, also a realm delete, register a second target for that realm. Run `meho targets describe <first target> --json` and copy its values: `meho targets add <name> --product keycloak --host <host> --port <port> --auth-model <auth_model> --secret-ref <secret_ref> --extra admin_realm=<admin_realm of the first target> --extra managed_realm=<realm>`. Copy every other connection setting the first target has too: `--fqdn`, `--verify-tls=false`, `--tls-ca-pin`, `--tls-server-name`, `--vpn-required`, `--preferred-impl`, `--version`, `--secret-field` and each other `--extra`. Only the name and the managed realm change. Leave out a setting the first target does not have. Then send the call to that target. To create a new realm, register a target that names that realm as its managed realm, and create the realm through it. If an operation says that Keycloak did not answer with the managed realm, set `managed_realm` of the target to the name exactly as Keycloak shows it. A call that names the managed realm still works. `keycloak.realm.delete` still needs its `realm` value: give the managed realm. In the other calls the `realm` value stays for now and will be removed later: leave it out.
