## Note
An admin (a tenant admin or a platform admin) makes a change of rights alone. A change of rights that an admin makes with a click in the web console, after the same sign-in as for an approval there, runs at once, and its audit row says so (`rights_change_run: admin_in_web_console`). A change of rights asked with a token (the command line, REST, MCP) or by an AI agent waits, and only an admin approves it, with a click in the web console. That admin may be the person who asked; the audit log records a self-approval. An admin may change their own login, for example their own passkey or group. The policy file import (`policy.apply`) and the category edit (`policy.classify`) follow the same rules. The command line and REST refuse to approve a change of rights with "This is a change of rights. Approve this change of rights in the web console." A change of rights that reads, writes or makes a credential, a `destructive` one, one with the "always wait" mark, and a `secret.move` with a `keycloak:` side always wait. A change that can give platform admin rights still needs a platform admin. A waiting request follows these rules at the upgrade. See https://evoila.github.io/meho/latest/guides/approvals-and-break-glass/#changes-of-rights.

## Action
Tell your admins that they approve a change of rights in the web console, not with `meho approvals approve`. Scripts that approve a change of rights on the command line or over REST must stop doing so. No schema action.
