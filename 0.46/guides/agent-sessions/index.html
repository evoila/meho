    Agent sessions¶

    MEHO can keep a copy of the agent sessions that people upload. A session is the record of one agent conversation. For Claude Code, that is the transcript file <session-id>.jsonl and the folder <session-id>/ next to it.

    MEHO stores the files in S3-compatible object storage that you bring. That is a file store with the Amazon S3 interface, for example MinIO. MEHO writes one index row per session in its own database.

    This page shows how to turn the store on with Helm values, who may do what, and how long MEHO keeps a session.

    Prerequisites

    • A MEHO install from the Helm chart (Install).
    • An S3-compatible object storage, a bucket in it, and an access key that may read, write and delete objects in that bucket.
    • A Vault (or the built-in OpenBao) that MEHO reads with its scheduler token (Scheduler).

    What MEHO keeps, and what it never keeps¶

    MEHO keeps:

    • the files of each upload, after a secret check, in your bucket;
    • one index row per session: tenant, session id, who uploaded it, project, app, start and end time, state (open, ended or unfinished) and the file hashes;
    • one audit row for each upload, read and delete.

    MEHO never keeps:

    • Secrets it finds. Every file passes a secret check before it is stored. Known secrets, such as private keys, bearer tokens, JWTs and password=... pairs, are replaced with [REDACTED:<pattern>].
    • File content in audit rows. An audit row holds the session id, counts and hashes only.
    • A session after its retention period. A cleanup job deletes it, with its files.
    • Sessions from a machine login. Only a person can upload. An agent, service or runner login gets 403.
    • The access key as a setting. MEHO reads the key from Vault for every call to the store. A rotated key works at once.

    When the secret check is not sure, the upload goes to quarantine. See Quarantine below.

    Turn it on¶

    The store is off until three values are set. Until then an upload, a download and a delete answer 503 session_store_not_configured.

    1. Store the access key in Vault¶

    Write the access key of the object storage to a Vault KV-v2 secret with two fields, access_key_id and secret_access_key.

    With the built-in OpenBao, use the path secret/services/session-store. The scheduler token may read it. Write it with an admin login:

    bao kv put secret/services/session-store \
  access_key_id=<access-key-id> \
  secret_access_key=<secret-access-key>

    With your own Vault, pick any path, and give the scheduler token's policy read on it. The setting takes the API path, with data/ in it:

    # Add to the policy of the scheduler token (VAULT_SCHEDULER_TOKEN).
path "secret/data/services/session-store" {
  capabilities = ["read"]
}

    Do not use a path under secret/meho/

    Every MEHO user may read secret/meho/*. Keep the access key on a path that only the scheduler token reads.

    2. Set the Helm values¶

    config:
  sessionStore:
    endpoint: "https://objects.example.com"
    bucket: "meho-sessions"
    credentialsVaultPath: "secret/data/services/session-store"

    Then run helm upgrade. MEHO reads the values when a pod starts.

    All values are strings. Write numbers and true / false in quotes. An empty value keeps MEHO's default:

    Value Default Meaning
    endpoint — URL of the object storage. Needed.
    bucket — The bucket for the files. Needed.
    credentialsVaultPath — Vault KV-v2 API path (secret/data/...) of the access key. Needed.
    region us-east-1 Region name sent to the store.
    retentionDaysDefault 90 Days a session is kept when its tenant set no period.
    maxUploadBytes 26214400 (25 MiB) Largest compressed upload.
    maxUnpackedBytes 268435456 (256 MiB) Largest unpacked upload.
    maxFiles 2000 Most files and folders in one upload.
    cleanupEnabled "true" Run the cleanup job.
    cleanupIntervalSeconds 3600 Seconds between cleanup runs (at least 60).

    A wrong value, such as maxFiles: "many", stops helm install and helm upgrade with a schema error.

    3. Check it¶

    The config map of the release now holds the three SESSION_STORE_* variables:

    kubectl get configmap <release>-config -o yaml | grep SESSION_STORE_

    The first upload shows whether the store works:

    • 503 session_store_not_configured: a needed value is missing.
    • 502 session_store_unavailable: MEHO cannot reach the store, or cannot read the access key from Vault.

    meho sessions list reads only MEHO's own index, so it works even before the store is set up.

    Who may do what¶

    Each right maps to the lowest tenant role that has it. Only a person may use the session routes.

    Right Lowest role How
    Upload own sessions read_only POST /api/v1/sessions
    List sessions operator meho sessions list, GET /api/v1/sessions
    Read a session operator meho sessions show, GET /api/v1/sessions/{session_id}
    Delete a session tenant_admin meho sessions delete, DELETE /api/v1/sessions/{session_id}
    Open an upload in quarantine tenant_admin GET /api/v1/sessions/{session_id}/uploads/{seq}
    Read or set the retention period tenant_admin GET / PUT /api/v1/sessions/retention

    Every call sees only the caller's tenant. A session of another tenant answers 404 session_not_found.

    Retention per tenant¶

    A session is old when its last upload is older than the tenant's retention period. The cleanup job deletes old sessions with their files, and writes an audit row for each.

    A tenant admin sets the period for the tenant, from 1 to 3650 days:

    curl -X PUT "https://<meho-host>/api/v1/sessions/retention" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"retention_days": 30}'

    {"retention_days": null} goes back to the default (retentionDaysDefault). GET /api/v1/sessions/retention shows the period and whether it is the tenant's own ("source": "tenant") or the default ("source": "default").

    Quarantine¶

    The secret check is careful on purpose. It sends an upload to quarantine when it is not sure, for example when:

    • a file is not UTF-8 text;
    • a name that looks like a secret still has a value, such as "password": "..." in JSON;
    • a private key starts or ends in another upload.

    A quarantined upload is stored, with the known secrets replaced. Only a tenant admin can download it. An operator gets 403 session_upload_quarantined, and MEHO writes an audit row for the refused download. meho sessions show marks the upload as in quarantine.
