## Note
Every `k8s.apply` waits for a person on every call, for every kind of object, in every document of a manifest and every item of a list object. There is no list of kinds that keep the rules of `k8s.apply`. No standing grant, no agent grant and no run approval covers it, also not as a step of a multi-step run. Grant create, agent grant create and run approval create refuse `k8s.apply`. The operations made from an ingested Kubernetes API file follow the same rule: every `POST`, `PUT`, `PATCH` or `DELETE` on the path of an object or of a collection of objects waits the same way, for every kind, also when the paths of the API file have a prefix in front. The rule reads the path of every operation made from an ingested API file, whatever the product: an API file of another product whose paths have the same form (`/api/v1/namespaces/...`, `/api/v1/<cluster-wide core kind>/...` or `/apis/<group>/<version>/...`) gets the same rule. A read, a `/status` or `/scale` write, and the `status` and `finalize` writes of a Namespace keep their rules. A sensor of `k8s.apply` or of such a write is refused at create and reads `unknown`. The card of a `k8s.apply` names every command that the manifest shows only by its size, also one under a field of a custom kind; an entry that is too large shows the start of what it runs and says that it is cut.

## Action
A deploy run, a service login or an agent that applies objects under a grant or a run approval now waits for a person at each apply: plan for a person to approve each apply in the console or the CLI. Find the grants, agent grants and run approvals that name `k8s.apply` or an operation made from an ingested Kubernetes API file, and also those on such operations of other ingested API files, with `meho service-principals grants list`, `meho agent grant list` and `meho approvals runs list`, and remove them: they never run such a call. Remove each sensor of `k8s.apply` or of an ingested Kubernetes write; it reads `unknown`. No schema action.
