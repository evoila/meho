## Note
A `k8s.apply` waits for a person on every call unless every object in its manifest is a plain object: `Service`, `Namespace`, `ServiceAccount`, `PersistentVolumeClaim`, `LimitRange`, `ResourceQuota` (core group), `NetworkPolicy` (`networking.k8s.io`), `PodDisruptionBudget` (`policy`), `HorizontalPodAutoscaler` (`autoscaling`) and `PriorityClass` (`scheduling.k8s.io`). MEHO reads the object by API group and kind, so a Knative `Service` waits and a core `Service` does not. A `Namespace` with a label or an annotation waits. A `Service` waits unless its type is `ClusterIP` or not set and it has no `externalIPs`. A `ConfigMap`, an `Ingress` and an `IngressClass` wait. Every other object waits, also every custom kind of a CRD (for example a Helm chart, a workflow, a pipeline run or a GitOps application), a webhook or admission policy, an API service, a CRD and a certificate signing request. No standing grant, no agent grant and no run approval covers such a call, also not as a step of a multi-step run. The operations made from an ingested Kubernetes API file follow the same list: a `POST`, `PUT` or `PATCH` of an object that is not plain waits the same way, also when the paths of the API file have a prefix in front. A write of a `Namespace` or a `Service` through such a file always waits, and so does a write of a cluster-wide core object such as a node or a volume. A `/status` or `/scale` write, the `status` and `finalize` writes of a Namespace, and a read keep their rules. A sensor of such a write is refused at create and reads `unknown`. The card of a `k8s.apply` names every command that the manifest shows only by its size, also one under a field of a custom kind; an entry that is too large shows the start of what it runs and says that it is cut. Who waits now: a run, a service login, an agent or the automation engine that used a grant on `k8s.apply` or on an ingested Kubernetes write to apply other objects.

## Action
Find the grants, agent grants and run approvals that name `k8s.apply` or an operation made from an ingested Kubernetes API file, with `meho service-principals grants list`, `meho agent grant list` and `meho approvals runs list`, and the sensors of such an operation. An apply of a `ConfigMap`, an `Ingress`, an `IngressClass` or a `Service` with another type or `externalIPs` under a grant or a run approval now waits for a person. For each deploy run that applies objects other than the plain ones, a person must approve each apply in the console or the CLI: plan for this before the run. Remove each sensor of an ingested Kubernetes write that now waits; it reads `unknown`. No schema action.
