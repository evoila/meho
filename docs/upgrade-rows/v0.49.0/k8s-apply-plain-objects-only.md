## Note
A `k8s.apply` waits for a person on every call unless every object in its manifest is a plain object: `ConfigMap`, `Service`, `Namespace`, `ServiceAccount`, `PersistentVolumeClaim`, `LimitRange`, `ResourceQuota` (core group), `Ingress`, `IngressClass`, `NetworkPolicy` (`networking.k8s.io`), `PodDisruptionBudget` (`policy`), `HorizontalPodAutoscaler` (`autoscaling`) and `PriorityClass` (`scheduling.k8s.io`). MEHO reads the object by API group and kind, so a Knative `Service` waits and a core `Service` does not. A `Namespace` with a label or an annotation waits, and so does an `Ingress` with an annotation, a label or a TLS entry. Every other object waits, also every custom kind of a CRD (for example a Helm chart, a workflow, a pipeline run or a GitOps application), a webhook or admission policy, an API service, a CRD and a certificate signing request. No standing grant, no agent grant and no run approval covers such a call, also not as a step of a multi-step run. The operations made from an ingested Kubernetes API file follow the same list: a `POST`, `PUT` or `PATCH` of an object that is not plain waits the same way, also when the paths of the API file have a prefix in front. A write of an `Ingress` through such a file always waits. A `/status` or `/scale` write and a read keep their rules. A sensor of such a write is refused at create and reads `unknown`. The card of a `k8s.apply` names every container; an entry that is too large shows the start of what it runs and says that it is cut. Who waits now: a run, a service login, an agent or the automation engine that used a grant on `k8s.apply` or on an ingested Kubernetes write to apply other objects.

## Action
Find the grants, agent grants and run approvals that name `k8s.apply` or an operation made from an ingested Kubernetes API file, with `meho service-principals grants list`, `meho agent grant list` and `meho approvals runs list`, and the sensors of such an operation. For each deploy run that applies objects other than the plain ones, a person must approve each apply in the console or the CLI: plan for this before the run. Remove each sensor of an ingested Kubernetes write that now waits; it reads `unknown`. No schema action.
