## Note
With `POLICY_APPROVER_ROUTING` on, the install's approver routing is a floor: a tenant's routing can only make it narrower. A person must be in the install's entry and in the tenant's entry. A tenant policy import with a wider routing entry is refused, and the message names the category and the install's groups. A wider tenant entry stored before the upgrade no longer widens anything. At the approve click MEHO also checks the install's current routing. A tenant may still give an operation another category for its own rules; the install's routing for the operation still applies, with the category that the install's file alone gives it. A call that started to wait while `POLICY_APPROVER_ROUTING` was off keeps the older rule after the switch is turned on, until it is decided or runs out. Migration `0173` adds two columns that may be empty: `approval_request.approver_category` and `approval_request.approver_install_category`. A request that already waits for routed approvers gets the empty text in both: MEHO does not know its category. At the click such a request is refused when an install entry that matches on `category` could fit it.

## Action
**Nothing to do** while `POLICY_APPROVER_ROUTING` is off. Otherwise run `meho policy diff --scope install` with the install's current file: each warning names a tenant entry that is wider. Fix those tenant files before their next import. Reject a request that waited before the upgrade and is refused for its unknown category, and start the call again. See [The install's routing is a floor](https://evoila.github.io/meho/latest/guides/policy-file/#the-installs-routing-is-a-floor).
