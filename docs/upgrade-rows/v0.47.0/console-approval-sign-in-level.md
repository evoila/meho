## Note
An approval in the web console asks for the same sign-in level as one on the command line. The console has a second Keycloak client, `meho-web-approve` (backplane setting `UI_KEYCLOAK_APPROVE_CLIENT_ID`), with the secret of `meho-web`, bound to the login flow `meho approval sign-in level`. It is used only for the new sign-in before an approve; the normal console login does not change. `APPROVAL_SIGN_IN_LEVEL` counts for the console too: under `required` (and under `auto` when this client's binding is right) the Approve button needs this sign-in with the level `meho-approve`, and a normal console session gets a **Sign in to approve** link instead. Under `observe` the console approves as before and records the level it saw. Migration `0173` adds the column `web_session.approval_token` that may be empty; no existing row changes.

## Action
**Built-in Keycloak:** nothing to do; the upgrade adds the client and binds it. **Your own Keycloak:** create `meho-web-approve` with the secret of `meho-web` and the redirect URI `https://<host>/ui/auth/approval-callback`, then run `meho admin keycloak bootstrap-clients` or bind it to the flow by hand ([The console approval client](https://evoila.github.io/meho/latest/install/keycloak-realm/#the-console-approval-client-meho-web-approve)). Until it exists, `auto` keeps the console as before. A person with only a company account approves with the passkey touch once the level is required.
