## Note
An agent, runner, add-on or other service login now reads only the audit rows of its own calls, whatever role it has: in `POST /api/v1/audit/query` and its filters (also `has_trace`), the class counts, `show`, the trace read, `by-work-ref`, `who-touched`, the MCP tool `query_audit`, the operation `audit.loose_rows` and every session replay. A row or session of another login answers like one that does not exist. The `shape="tree"` replay of `query_audit` holds only the rows of the caller's own calls, for a person too; the `Mcp-Session-Id` header does not change which rows it shows. The agent or service login that asked for a call a person approved still reads the trace of that call. People keep every row of their tenant. A paired add-on that reads the audit log with its service login now gets only the rows of its own calls. An agent sees the run of a call a person approved through the trace of that call, not in the row list.

## Action
A service login that read the audit rows of other logins now gets fewer rows. To look into the calls of others, a person runs the query.
