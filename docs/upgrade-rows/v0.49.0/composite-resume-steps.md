## Note
When a multi-step operation waits for approval at one of its steps and goes on after the approval, MEHO does not send the steps that already ran again. MEHO stores the steps of the run, with their results, on the approval request and replays them; the result of a step that reads, writes or makes a credential is never stored. These runs finish: a run with a credential write or make that ended well (it is not sent again and gives back no result), and a run with a credential read that needed no person (MEHO checks its policy again and sends the read again after the approval only when the policy still lets it go ahead with no person). A credential read that a person approved is never sent again: a later step that needs approval stops the run at once with `composite_resume_read_not_sent`, which names the read, and no approval request is made. A credential read whose policy now says it must wait, or is denied, is not sent again either, and the run stops with the same error. These runs stop with `composite_resume_step_outcome_unknown`: a run with a step whose end MEHO does not know (also a credential write with a lost answer); a later step of that run that needs approval stops it at once, with no approval request. A run whose credential read gives a new answer that changes the approved step stops with `composite_resume_repeats_write`, and that step is not sent. A second step that waits in the same run waits for its own approval (the error `composite_resume_multi_gate_unsupported` is gone). A request of a step of a multi-step operation is never run again through `POST /api/v1/approvals/{id}/rerun` (refusal `multi_step_run`, which replaces `input_not_kept`). Connector authors run each change of a multi-step operation that can go on after an approval through `run_governed_subop`.

## Action
A multi-step run that waits for approval at the upgrade does not go on: its request expires at start-up like every request of the older release, and an approved one that has not run yet is refused. The requester starts the operation again.
