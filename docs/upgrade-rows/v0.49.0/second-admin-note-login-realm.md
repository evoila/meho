## Note
The one-admin note shows for a waiting change of rights in MEHO's own login realm, in `master` or in the target's admin realm, or where MEHO could not make sure that it is not, when the person who asked is the only admin of the tenant. There a platform admin must approve the change. Its text is "A platform admin must approve this change. It is in MEHO's own login realm, in `master` or in the target's admin realm, or MEHO could not make sure that it is not. You can approve it yourself only if you are a platform admin and asked for it in the web console. MEHO found no other admin in this tenant." with a link to the guide. On a retry of an approved request, the note keeps only "MEHO found no other admin in this tenant." and the link. `policy.apply`, `policy.classify` and a change in any other realm get no one-admin note. The "no admin" note ("This tenant has no admin." and the link) shows for every waiting change of rights with a sure count of zero admins, also `policy.apply`, `policy.classify` and a change in any other realm. The `meho doctor` line "second admin" warns whenever the tenant has one admin; only its text and its fix are new. It warns "This tenant has only one admin. Some changes of rights in MEHO's own login realm need a platform admin other than the person who asked." Its fix says "add a second platform admin in Keycloak (in MEHO-Platform-Admins)". No field is removed: `approvals.rights_change_admins` in `/api/v1/health` and `meho_status`, and `extras.approval_note`, keep their name and shape. See https://evoila.github.io/meho/latest/guides/approvals-and-break-glass/#changes-of-rights-need-another-admin.

## Action
A script that reads the text of the note or of the doctor warning reads the new text. When the line "second admin" warns, add a second platform admin in Keycloak (in `MEHO-Platform-Admins`). No schema action.
