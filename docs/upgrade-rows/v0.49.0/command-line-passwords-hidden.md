## Note
A password or token on a command line is now hidden. Command lines in operation results, approval cards, traces, broadcast messages and error texts show `[REDACTED:command_line_secret]` in place of the password. This covers long options such as `--password …` and `--api-key …`, short options after their tool (`sshpass -p …`, `mysql -p…`, `sqlcmd -P …`, `ldapsearch -w …`, `curl -u user:…`, `smbclient -U user%…`), and environment style names such as `DB_PASSWORD=…`. The rest of the command line stays readable. A quoted password right before a shell operator such as `;` is hidden inside its quotes, also when it is made of several quoted parts. A password before such an operator that the `api_key` rule does not hide, such as a short one or one with an escaped space or quote, is hidden whole after the `api_key` rule and shows `[REDACTED:command_line_secret_rest]`. An ANSI-C quoted password (`$'...'`) is hidden whole. When the end of a password is not known, because its quote never closes, the rest of its command is hidden up to the next `;`, `|`, `&` or line end. An empty password (`''`) stays. A tool name is read as the tool only when it is the program that runs: at the start of a command, also with any path, after a command such as `sudo`, `nice`, `timeout` or `xargs` that runs it, or after `-exec` of `find`. A tool name right after an option, or as an argument of a command such as `find`, is not read as the tool, also after `sudo` or a quoted argument. An option such as `--ask-pass` or `--skip-password` takes no value, so the next word stays. A value that the `api_key` rule hides already stays as it was. Inside a JSON string or a double-quoted command, an escaped line end or tab ends the value, so the words after it stay readable. There an escaped line end also ends the command of a tool, so an option on a later line stays readable. A JSON string is decoded and read like plain text, also a JSON string inside another JSON string, up to three levels deep, so these forms are hidden there too. Every part that was hidden before is still hidden, and a JSON log line that parsed before still parses. A value that was hidden already (also an older mark such as `***REDACTED***`, or only `*` characters) stays as it is. A command line with no password is shown as before. Not hidden yet, see Task #6747: connection strings, a database login with user, password and service, the text of an XML element named like a secret, a single-quoted command that is joined with an escaped single quote before the option, a quoted command or value that runs over a line break, tool names in capitals or with `.EXE`, the part of a value after an escaped line end or tab, a value that the `api_key` rule hides only in part, and the other forms that Task lists. The raw copy in an audit row is not changed by this rule.

## Action
None for most operators. A script or a check that reads a password from a command line in a result now gets the hidden mark: read the password from Vault or the target's credentials instead.
