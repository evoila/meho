## Note
A new switch `K8S_APPLY_PREVIEW_DRY_RUN`, off by default. With it on, `preview_operation` for `k8s.apply` asks the cluster what the apply would do: it sends a server-side apply for every document of the manifest, with the target's own cluster account. Every request that can change something carries `dryRun=All`; the only other requests are `GET` reads of the cluster's API list (`/version`, `/api`, `/apis` and the group paths). Nothing is stored on the cluster. The preview then shows for each document whether the apply creates it, changes it or is refused, or that the cluster did not check it. MEHO records each such preview in one audit row of the class read. Only a caller with the role Operator or higher, whom the policy does not refuse the apply, gets this dry run. The apply itself waits for approval, and its approval request is not changed. With the switch off, nothing changes.

## Action
None. To turn it on, set the switch with Helm: `extraEnv: [{name: K8S_APPLY_PREVIEW_DRY_RUN, value: "true"}]`. The cluster account of each Kubernetes target needs the rights of the real apply; the dry run needs the same rights.
