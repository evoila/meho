## Note
In MEHO's own login realm, in `master` and in the target's admin realm, a platform admin now approves every Keycloak write, and every `secret.move` that reads from or writes to one of these realms. The one exception is a write that sets only keys from a short list that cannot touch sign-in or rights: `displayName` of `keycloak.realm.update`, `name` and `description` of `keycloak.client.update`, and `firstName` and `lastName` of `keycloak.user.update`. When a target's admin realm is the realm it manages, a platform admin approves every Keycloak write on that target, except a write that sets only these keys. When a param names the realm, MEHO reads that realm from Keycloak and judges the name Keycloak answers with. When MEHO cannot read which realm a write changes, it counts as the login realm. The approval card says why. Right before an approved write runs, MEHO checks it again. In other realms, the approvers stay the same.

## Action
Many Keycloak approvals in these realms now need a platform admin, where a tenant admin was enough. Make sure a platform admin can approve them. In these realms, no standing grant and no run approval clears a Keycloak write: a call of a service login waits for a person to approve it. A Keycloak write or a `secret.move` with a Keycloak side that was approved before the update and has not run yet is refused when its run starts, in every realm: send it again. `keycloak.realm.create` accepts only plain ASCII characters in the name of the new realm: a name with a letter with an accent is refused. No schema action.
