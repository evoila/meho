    Words we use¶

    MEHO has some words of its own. This page explains each one in a few plain words, in A to Z order. Each entry links to the page with more.

    This page is written by hand. It is not generated from the code.

    Approval¶

    Some changes wait until a person says yes. MEHO changes nothing on the system until then.

    More: Approvals

    Audit record¶

    MEHO saves one row for every call. It shows who did what, to which system, and when.

    More: Audit forensics

    Broadcast¶

    A shared feed where agents post what they plan, what they do, and what they finished. It helps people and agents stay out of each other's way.

    More: Broadcast

    Call an operation¶

    Run one operation on one target. MEHO checks the rules, uses the stored login, and writes an audit record.

    More: Run your first operations

    Connector¶

    The part of MEHO that talks to one kind of system. A generic connector is built from the vendor's API file, and a typed connector is written by hand.

    More: Connectors overview

    Connector version¶

    The end of a connector id, for example 1.x in k8s-1.x, names the product version line. The exact versions are on the Connectors page.

    More: Connectors

    Dashboard¶

    A group of sensors that MEHO shows as one combined state.

    More: Watch your estate with sensors

    Detected product and version¶

    MEHO finds the product and version of a target when it checks the target (a probe), and uses them to pick the connector. This is also called the fingerprint.

    More: Register targets and secrets

    Docs collection¶

    A set of documents that MEHO can search and answer questions from, when the docs add-on is on. A tenant can search only the collections it may use.

    More: Add-ons

    Five states¶

    Every sensor result is one of five states: ok, degraded, critical, unknown or skip. unknown means MEHO could not judge the result, and skip means the sensor is paused.

    More: Watch your estate with sensors

    Grant¶

    A permission that a person gives in advance to an automation login (a service principal), for example a build pipeline. With it, many caution and dangerous changes run without a wait; deletes, secret reads and changes of rights still wait for a person.

    More: Approvals

    Knowledge¶

    Notes for the whole team that MEHO and agents can search, for example how a vendor API works. They stay until someone deletes them.

    More: Memory and knowledge

    MCP¶

    Short for Model Context Protocol, the way AI tools connect to MEHO. MEHO gives them a short list of tools, not one tool for each system.

    More: MCP surface and scopes

    Memory¶

    Notes that can belong to one person, one target or the whole tenant. A note can expire.

    More: Memory and knowledge

    Operation¶

    One thing you can do on a system, for example list the pods of a cluster. Each operation has an op_id and a risk level.

    More: Run your first operations

    Operation group¶

    A set of related operations of one connector. It has a short hint on when to use it, so you can narrow your search.

    More: Run your first operations

    Operator tools¶

    Extra tools for admin work, such as connectors, agents and schedules. A session sees them only when it asks for the extra right mcp:admin at sign-in.

    More: MCP surface and scopes

    op_id¶

    The name of one operation, for example k8s.pod.list. You give it when you call or preview an operation.

    More: Run your first operations

    Preview¶

    Shows what a call would send, before you run it, and sends nothing. For some operations a preview is not available.

    More: Run your first operations

    Result link¶

    When a result is large, MEHO gives you a sample and a link to the full result, also called a result handle. The link expires, and only you can read it.

    More: Run your first operations

    result_query¶

    The tool that reads a large result back by its result link. You can read it page by page, or ask for a filtered view.

    More: Run your first operations

    Risk level¶

    Every operation is safe, caution, dangerous or destructive. The level helps decide what waits for approval.

    More: Approvals

    Runbook¶

    A saved list of steps, where each step calls an operation or asks a person to do something. Each step has a check before the run goes on.

    More: Author and run runbooks

    Sandbox mode¶

    A setting for a MEHO install that holds only test systems you can throw away. There, an admin may let an automation login also run deletes without a wait.

    More: Approvals and break-glass

    Satellite runner¶

    A small copy of MEHO that runs inside a network that the main MEHO cannot reach. It calls out to MEHO, runs its checks, and sends the results back.

    More: Reach isolated networks with a satellite gateway

    Sensor¶

    A check that MEHO runs on a schedule. It calls one safe operation and judges the answer by fixed rules, with no AI.

    More: Watch your estate with sensors

    Target¶

    One system that MEHO works on, for example a Kubernetes API or a vCenter. MEHO keeps how to reach it and a reference to its login, never the password.

    More: Register targets and secrets

    Tenant¶

    A separate space in MEHO, with its own systems and passwords.

    More: One person in several tenants

    Working surface¶

    The 26 tools that every MCP session sees by default. Four of them need the docs add-on, so some sessions see 22.

    More: MCP surface and scopes
