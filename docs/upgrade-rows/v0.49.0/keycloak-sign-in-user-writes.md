## Note
MEHO now refuses Keycloak writes that would lock it out of a Keycloak target. When the user the target signs in with (by its user name or its email, or the service-account user of its client) is the user of `keycloak.user.disable`, `keycloak.user.required_actions.update`, `keycloak.user.reset_password`, `keycloak.user.credential.delete`, `keycloak.group.member.remove`, `keycloak.role_mapping.client.remove`, `keycloak.user.update` of the user name or email, or a `secret.move` into its password, MEHO refuses the call before it waits for approval and again when an approved request runs. A request that waits for approval from before the upgrade is refused when it runs. Nothing is written. The answer of `keycloak.user.required_actions.update` now gives `required_actions` as read back from Keycloak after the write, and `null` when MEHO does not know it.

## Action
To change the user a target signs in with, first give the target another admin login, or make the change in the Keycloak admin console. A tool that reads `required_actions` from `keycloak.user.required_actions.update` must accept `null`. No schema action.
