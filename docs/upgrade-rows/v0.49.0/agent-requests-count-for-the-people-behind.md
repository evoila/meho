## Note
A request made by an agent, an add-on (a service login) or a runner now counts as a request of the people behind it: who set it up or owns it, who gave one of its grants in force, who wrote or last changed its agent definition, who made one of its schedules or event sources, and who started or handed over its runbook run. Such a person may approve the request only where they may approve their own change, and a change of rights always needs another admin. When MEHO knows nobody behind the login, only an Admin may approve. The request card, `meho approvals show` and the REST answer (`people_behind`) name these people. Migration `0176` adds four columns and fills who last changed each agent definition from the audit log. See https://evoila.github.io/meho/latest/guides/approvals-and-break-glass/#a-request-of-an-agent-counts-as-a-request-of-the-people-behind-it.

## Action
An Operator who set up an agent or an add-on, or gave it a grant, now gets a refusal when they approve its requests: another person approves them. On an install with one admin, the admin approves the agent's requests as their own change, and a change of rights made by an agent needs a second admin. For a login that MEHO knows nobody behind (made only in Keycloak), an Admin approves its requests; a grant given in MEHO makes the giver a known person for its next requests. No schema action: the migration runs at start.
