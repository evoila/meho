A citation whose source has no public URL was a dead end on the search / ask cards; this view gives it a consistent view-source affordance -- an entitlement-checked, shareable permalink that names *where a grounded answer's claim came from* and links onward to the collection. Extends ``base.html`` so the chrome matches the console; sets ``active_surface="corpus"`` so the sidebar highlight stays on the corpus surface. The GET view is read-only -- no forms, no CSRF token. Why not the chunk body: the retrieved chunk's content is already shown on the citation card, and the backend-agnostic search interface has no fetch-by-id seam to re-load it here (see ``chunk_detail.py``). So the GET view renders identity + provenance, not a re-fetched body. Read around the hit (#3948): a result card's "Read around this hit" form POSTs here for a collection that offers read. The page then also shows the text around the hit (escaped by autoescape, whitespace kept) and, when the backend has more, a "Show more" form that posts the same handle with the ``next`` cursor. The POST keeps the GET view's 404 / 403 for an unknown or not-entitled collection; every other read refusal shows one neutral note instead.
