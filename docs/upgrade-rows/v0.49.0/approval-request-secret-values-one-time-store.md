## Note
When a call waits for approval and its inputs hold a secret value, MEHO keeps the real inputs in the encrypted one-time store of the request, and the stored request and its approval card show a marker in place of each secret value. The same holds when the inputs of the multi-step operation around a waiting step hold one. A secret value is a value under a secret name, or a value in a field that a connector marked as one that may hold a secret. A number under a secret name counts when the last word of the name names the secret (`password`), not a setting of it (`password_max_age_days`). The approved run sends the real values once, also when an AI agent that waited runs it. When the connector sends such a value back, the stored result and the audit row of the run show the marker. A re-run of a failed run needs the inputs sent again. Stored inputs run only when they match the approved hash. Without a valid `APPROVAL_HANDOFF_ENCRYPTION_KEY`, MEHO refuses such a call instead of letting it wait, also when it is a step of a multi-step operation.

## Action
Check that `APPROVAL_HANDOFF_ENCRYPTION_KEY` is set to a valid key (the status page shows it). The upgrade ends the approval requests that still wait, as every upgrade does: ask the people who sent them to send the calls again after the upgrade. No schema action.
