    Connector inventory¶

    This page lists every MEHO connector in two tables. The first table lists the open source connectors of the public image. The second table lists the connectors of evoila's enterprise pack, a commercial add-on with the VMware and VCF connectors. Agents and operators drive all of them through the same governed surface — pick a connector, list its operation groups, search operations, then call — so no tool name carries a vendor name.

    You can add your own connectors the same way as the enterprise pack: see Write a connector package.

    Open source connectors (public image)¶

    These connectors are in the public image, generated from the in-process connector registry. Each row is one registered implementation. The Docs column links to the connector's page in the source repository.

    MEHO has two kinds of connector, both first-class and indistinguishable to an agent. Generic connectors are built by ingesting a vendor's protocol spec (OpenAPI, GraphQL, WSDL, proto); typed connectors are hand-coded against a vendor SDK or transport where no usable spec exists. The Kind column is populated only where MEHO's published connector-spec catalog states it, and is blank otherwise — it is a property of how a connector's operations are sourced, not something this table infers.

    Versions and how a connector is chosen¶

    Supported versions is the product-version range an implementation advertises. Where a product has more than one implementation — a modern and a legacy one, say — both are registered and MEHO resolves the right one per target from the target's fingerprint, so one estate spanning old and new versions just works. A connector can also state the target versions its operations work on. MEHO checks this range each time an operation runs (at dispatch time), also when the call names the connector itself. Outside the range, MEHO refuses the call with unqualified_target_version, and a Sensor on that connector can read unknown. So pick the connector whose version matches the target, for example vmware-rest-8.0 for vCenter 8.0.x and vmware-rest-9.0 for vCenter 9.0.x.

    Maturity and readiness¶

    This inventory lists what is registered; it does not restate a ship-state. Feature-level maturity — GA, beta, or experimental — is published in the feature maturity index. Per-release, per-connector ship-state (dispatch + catalog, loader-wired, or production-ready) is stated in the changelog under the connector release-notes convention. The two-connector model is described in the architecture overview.
