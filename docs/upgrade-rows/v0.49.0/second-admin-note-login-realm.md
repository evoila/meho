## Note
The note on a waiting change of rights and the `meho doctor` warning in the line "second admin" appear only for changes of rights in MEHO's own login realm. There a platform admin must approve a waiting change of rights. The note shows when the person who asked is the only admin of the tenant. Its text is "This change is in MEHO's own login realm, so a platform admin must approve it. You can approve it yourself only if you are a platform admin and asked for it in the web console. MEHO found no other admin in this tenant." with a link to the guide. On a retry of an approved request, the note keeps only "MEHO found no other admin in this tenant." and the link. A change in another realm, `policy.apply` and `policy.classify` get no note. With one admin, `meho doctor` warns "This tenant has only one admin. Some changes of rights in MEHO's own login realm need a platform admin other than the person who asked." Its fix says "add a second platform admin in Keycloak (in MEHO-Platform-Admins)". No field is removed: `approvals.rights_change_admins` in `/api/v1/health` and `meho_status`, and `extras.approval_note`, keep their name and shape. See https://evoila.github.io/meho/latest/guides/approvals-and-break-glass/#changes-of-rights-need-another-admin.

## Action
A script that reads the text of the note or of the doctor warning reads the new text. When the line "second admin" warns, add a second platform admin in Keycloak (in `MEHO-Platform-Admins`). No schema action.
