## Note
A write to a sub-part of a Kubernetes object, through an operation made from an ingested API file, waits for a person on every call. A sub-part write is a `POST`, `PUT`, `PATCH` or `DELETE` on a path that goes on past the name of the object, for example a pod's `eviction` or `binding`, a Namespace's `finalize`, or the action of an add-on API under `/apis/<group>/<version>/...`. No standing grant, no agent grant and no run approval covers it, also not as a step of a multi-step run. Grant create, agent grant create and run approval create refuse such an operation. Only `status` and `scale`, right after the name of the object, keep the rules of their operation, for every kind. Reads do not change. A sensor of such an operation is refused at create and reads `unknown`.

## Action
Find the grants, agent grants and run approvals that name such an operation with `meho service-principals grants list`, `meho agent grant list` and `meho approvals runs list`. Look for op ids with a write method and a path that goes on past the name of the object, other than `/status` and `/scale`. Remove them: they do not cover the call. Remove each sensor of such an operation; it reads `unknown`. Plan for a person to approve each call in the console or the CLI. No schema action.
