## Note
A password or token on a command line is now hidden. Command lines in operation results, approval cards, traces, broadcast messages and error texts show `[REDACTED:command_line_secret]` in place of the password. This covers long options such as `--password …` and `--api-key …`, short options after their tool (`sshpass -p …`, `mysql -p…`, `sqlcmd -P …`, `ldapsearch -w …`, `curl -u user:…`, `smbclient -U user%…`), and environment style names such as `DB_PASSWORD=…`. The rest of the command line stays readable. A value that the `api_key` rule hides already stays as it was. Every part that was hidden before is still hidden, and a JSON log line that parsed before still parses. A value that was hidden already (also an older mark such as `***REDACTED***`, or only `*` characters) stays as it is. A command line with no password is shown as before. Not hidden yet, see Task #6747: connection strings, a database login with user, password and service, the text of an XML element named like a secret, a quoted value that runs over a line break, strings inside JSON strings, inside a JSON string or a double-quoted command the part of a value after an escaped double quote, and a value that the `api_key` rule hides only in part. The raw copy in an audit row is not changed by this rule.

## Action
None for most operators. A script or a check that reads a password from a command line in a result now gets the hidden mark: read the password from Vault or the target's credentials instead.
