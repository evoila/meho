## Note
With the new setting `RUNNER_CHECKS_ENABLED=true` (off by default), a check that has a `runner_name` runs on that runner at its site, and the result the runner posts counts like the result of a central check. It sets the state, shows on the dashboard ("runs at: runner `<name>`"), sends mails on a change and on recovery, and can start the investigator. MEHO reads the rule of the check on the answer, so a runner never sends a state. An answer over 256 KB, or a batch over 4 MB, gives the check the state `unknown` with the reason "answer too large". A result needs the runner's own time: a runner time more than 30 seconds later than MEHO's clock is refused and named in the answer, and a result without one is stored but not counted. When every result of a batch is refused, MEHO answers 422 with the code `results_refused`. A batch that MEHO refuses three times, over at least 5 minutes, goes to the `set-aside` folder inside the runner's spool folder; the runner tells MEHO, also after a restart, and the check reads `unknown` with the reason `result_refused`. The runner runs each check on the check's own schedule. When a runner stops reporting, its checks read `unknown`. With the setting off, MEHO only stores runner results, the answers do not show `runner_name`, and the clean-up job deletes no runner results. Migration `0187` adds the nullable `sensor.runner_name` and `sensor.runner_produced_at` columns and an index on `runner_check_results.received_at`. Migration `0189` adds `runner_assignments.set_aside_count` (default 0) and `runner_assignments.set_aside_last_at`, the count and the time of the set-aside batches of each runner. Migration `0190` adds the table `runner_refused_results`, so MEHO counts each refused result once, also with more than one MEHO process. A new setting `RUNNER_CHECK_RESULTS_RETENTION_DAYS` (default 7, `0` keeps all) sets how long the clean-up job keeps raw runner results while `RUNNER_CHECKS_ENABLED` is on. See https://evoila.github.io/meho/latest/guides/satellite-gateway/#checks-that-run-at-a-site.

## Action
None. The setting is off by default, and the migration runs at start. To run checks at a site, update the runners first, then set `RUNNER_CHECKS_ENABLED=true` and create the check with `runner_name` (`meho sensor create --runner <name>`).
