## Note
Every Keycloak operation now reads the target's managed realm first and checks the realm name in Keycloak's answer. The name must be exactly the `managed_realm` of the target: the same letters, the same letter case and no space around it. MEHO refuses a Keycloak target whose `managed_realm` is not exactly the realm's name in Keycloak, also when only the letter case differs. The check runs before the call waits for approval, before `preview_operation` answers, and again when the call runs. A refused call stores no approval request and sends nothing more to Keycloak.

## Action
For each Keycloak target, compare its `managed_realm` (`meho targets describe <target>`) with the realm name that the Keycloak admin console shows. If they differ, also only in letter case, correct the realm name on the target. Start from the target as MEHO stores it now and change only `managed_realm`: an update sends the whole extras map and replaces the stored one, so do not reuse an older targets file, which can lack an extra that was added later. First find the name of your tenant: `meho tenants use` lists your tenants and marks the current one. Then read the target from the REST API with this command, which keeps the token off the command line: `printf 'header = "Authorization: Bearer %s"\n' "$(meho login --print-token https://<meho-host>)" \| curl --config - -H "Meho-Tenant: <tenant>" https://<meho-host>/api/v1/targets/<target>`. The `Meho-Tenant` header names the tenant, so the read also works for a login that is in more than one tenant. Write a file `fix-realm.yaml` with one entry under `targets:` that gives the `name`, `product` and `host` of that answer, and under `extras:` the whole `extras` object of that answer, pasted as it is (JSON is also YAML), with only the value of `managed_realm` changed to the name exactly as Keycloak shows it. Do not copy the extras from `meho targets describe --json`: it can round a large number. Run `meho targets import fix-realm.yaml --update --dry-run` and check that the plan updates only this target, then run `meho targets import fix-realm.yaml --update`. The update may wait for approval: then the command prints the approval id, and the change runs only after a person approves it. After the change ran, read the target again with the same `curl` command and check that `managed_realm` has the new name and every other extra still has the same value. Do not use `meho targets update --extra` for this: it replaces the whole extras map and stores every value as text.
