## Note
A change (PUT, POST, PATCH, DELETE) that a connector of MEHO sends is sent at most twice: it follows only a 307 or 308 to the same path, and every other redirect after the change ends the call. This holds also for the typed writes of Argo CD, Proxmox and Harbor. A read and a connector login follow a redirect on the same origin. The Azure and Entra connectors follow no redirect at all. A connector package keeps the rule of a read for every request until it declares that it names its logins (`names_its_logins`), so the logins of released packages keep working. The audit row of a change that ends on a 301, 302 or 303 says that the outcome is uncertain, also when the answer names no address. Each trace entry names the address MEHO asked for, also after a followed redirect; for an operation that sends a secret, a path segment that holds a value of the call is replaced by `[redacted]`. The new switch `REDIRECT_ON_CHANGE_RESULT` (off by default) decides only the answer of such a redirect: off gives the generic `connector_error` answer, on says what the HTTP code means and tells the agent not to send the change again. See https://github.com/evoila/meho/blob/main/docs/codebase/mcp.md.

## Action
None. Set `REDIRECT_ON_CHANGE_RESULT=true` to try the answer that says what the HTTP code means.
