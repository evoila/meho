## Note
Every Keycloak operation now reads the target's managed realm first and checks the realm name in Keycloak's answer. The name must be exactly the `managed_realm` of the target: the same letters, the same letter case and no space around it. MEHO refuses a Keycloak target whose `managed_realm` is not exactly the realm's name in Keycloak, also when only the letter case differs. The check runs before the call waits for approval, before `preview_operation` answers, and again when the call runs. A refused call stores no approval request and sends nothing more to Keycloak.

## Action
For each Keycloak target, compare its `managed_realm` (`meho targets describe <target> --json`) with the realm name that the Keycloak admin console shows. If they differ, also only in letter case, correct the realm name on the target with a targets file, so every other extra keeps its value and its type (a list, a map, `true` or `false`, a number). Write a file `fix-realm.yaml` with one entry under `targets:` that gives the `name`, `product` and `host` of the target as `targets describe` shows them, and under `extras:` the whole `extras` object from `targets describe --json`, pasted as it is (JSON is also YAML), with only the value of `managed_realm` changed to the name exactly as Keycloak shows it. Run `meho targets import fix-realm.yaml --update --dry-run` and check that the plan updates only this target, then run `meho targets import fix-realm.yaml --update`. Run `meho targets describe <target> --json` again and check that every other extra is still there with the same value. Do not use `meho targets update --extra` for this: it replaces the whole extras map and stores every value as text.
